# Nexus Hub v0.4 Architecture & Security Documentation

## 1. Overview
In Nexus Hub v0.4, process lifecycle supervision and local IPC boundaries are strictly managed by the Rust core workspace:
- **Flutter UI** never invokes `scrcpy`, `kdeconnect-cli`, `adb`, or OS shells.
- All command executions flow through a typed, bounded, per-user authenticated local IPC interface.
- Subprocess ownership is tracked with child handles, output limits, and explicit kill escalation.

---

## 2. Hexagonal Architecture & Crates
The Rust codebase is structured into isolated crates adhering to ports-and-adapters:

1. **`nexus-domain`**:
   - Contains core entity models (`DeviceInfo`, `StreamSession`, `DaemonCapabilities`), error types (`DomainError`, `ErrorCode`), and validation logic (`is_valid_device_id`).
   - Free from UI, framework, or platform dependencies.
   - Enforces strict separation between KDE Connect device IDs and ADB device serials.

2. **`nexus-adapter-kde`**:
   - Adapter implementing `KdeAdapter` for the upstream `kdeconnect-cli` executable.
   - Spawns child processes safely without shell interpolation (`runInShell: false` semantics).
   - Enforces execution timeouts (12 seconds default) and caps capture output to 12 KB to prevent memory exhaustion.

3. **`nexus-adapter-scrcpy`**:
   - Implements `ScrcpySupervisor` managing the upstream `scrcpy` executable.
   - Manages single-active-session concurrency invariants (`SessionAlreadyRunning` protection).
   - Asynchronously drains `stdout` and `stderr` to avoid OS pipe buffer deadlocks.
   - Monitors child exit status and surfaces broadcast events (`SessionStarted`, `SessionExited`, `SessionFailed`).
   - Idempotent stop logic with explicit SIGKILL escalation and confirmation deadline.

4. **`nexus-application`**:
   - Coordinates use cases (`HubApplication`) and capability negotiation across adapters.

5. **`nexus-ipc`**:
   - Wire contract definitions (`IpcRequest`, `IpcResponse`, `IpcNotification`, `WireMessage`).
   - Local transport server enforcing maximum frame size (64 KiB), maximum concurrent clients (8), and mandatory per-user session token authentication.

6. **`nexus-core`**:
   - Orchestrates the daemon startup, generates per-user auth credentials, starts the IPC server, and maintains optional backward-compatible LAN observation.

## 3. Threat Model & Security Controls

| Threat Vector | Mitigation in v0.4 |
|---|---|
| **Anonymous Localhost HTTP Exploitation** | Deprecated HTTP as a control surface. All control actions require authenticated IPC handshake using a session token stored in the user's OS runtime directory (`XDG_RUNTIME_DIR` / `%LOCALAPPDATA%\NexusHub\run`) with strict owner-only permissions. |
| **Command Injection / Switch Abuse** | Shell interpolation is forbidden. Device IDs and ADB serials are validated against `^[A-Za-z0-9_.:-]+$` (1..128 chars) and reject leading hyphens (`-`). |
| **Identity Conflation** | KDE Connect IDs and ADB serials are isolated into distinct typed fields and separate command routes. |
| **Resource & Buffer Exhaustion** | IPC message frame sizes are capped at 64 KiB. Subprocess output captures are capped at 12 KB. Stale sessions and unauthenticated connections are dropped. |
| **Zombies & Unresponsive Children** | Scrcpy processes are tracked via owned child structs. Stop requests issue graceful termination followed by explicit process kill escalation and a 3-second deadline. |

---

## 4. Upstream CLI Support & Verification Status
- **`kdeconnect-cli`**: Supported via PATH discovery or `NEXUS_KDECONNECT_PATH`.
- **`scrcpy`**: Supported via PATH discovery or `NEXUS_SCRCPY_PATH`.
- **Flutter Integration**: Communicates via `NexusIpcClient` over authenticated local IPC.
