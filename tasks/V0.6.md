# v0.6 — notifications, clipboard and SMS

Prerequisite: v0.4 IPC complete (v0.5 may run as separate branch only after shared contracts are stable).

Goal: real trusted KDE Connect compatibility first, no synthetic UI data.

Deliverables:
1. Map upstream KDE DBus and CLI interfaces for Linux, and documented available Windows/macOS adapters. Do not parse human-readable console text as a long-term stable machine protocol; prefer typed DBus endpoints where available.
2. Add capability matrix and explicit device pairing checks for notifications / clipboard / SMS. Verify Android app support and required permissions; never imply SMS support on iOS or unsupported Android versions.
3. Notifications: event subscription, bounded buffer, last-seen IDs and deduplication, replies only to user-approved actions.
4. Clipboard: manual enable/disable, MIME handling, bounded payloads and loop prevention using provenance ID or deterministic digest and TTL; define privacy policy.
5. SMS: only on devices supporting the official KDE Connect SMS plugin; explicit confirmation for send, show delivery failures; no background sends. Mask private contents in logs.
6. Tests: reconnect duplicate events, out-of-order events, bad encoding, disabled permissions, replay, clipboard loops, SMS send failure, blank/invalid recipients.

Exit gate: each UI surface shows live data from a paired device or clear unsupported state. Commit: `feat(sync): add trusted notification clipboard and SMS workflows`.
