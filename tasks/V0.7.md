# v0.7 — virtual camera and audio routing

Prerequisites: v0.4 lifecycle and v0.5 media engine verified. No camera/mic capture without conspicuous affirmative user consent.

Deliverables:
1. Capability/permission matrix: Linux PipeWire and v4l2loopback if installed/authorized; Windows virtual camera using supported Media Foundation based implementation or established signed third-party integration; macOS CoreMediaIO camera extension where feasible, with entitlement/signing constraints. Do not promise platform parity.
2. Add explicit StartCamera / StopCamera and StartMic / StopMic commands and visible capture indicator, privacy switches, correct device selection, error UI. Ensure crash/exit releases capture resources.
3. Use platform-native audio routing (Linux PipeWire, Windows WASAPI/Audio Graph as appropriate, macOS CoreAudio) with explicit output selection and resampling when needed; document virtual microphone restrictions.
4. Add bounded A/V sync buffers, jitter measurements, audio drift correction, camera FPS and device capability negotiation. Support at most one owner per device unless intentionally designed otherwise.
5. Tests: permission revoked mid-stream, unplug/replug, default audio output change, simultaneous clients, driver absent, suspend/resume, stop during startup, device released on force stop.

Exit gate: at least one platform verified end-to-end with OBS/meeting client and reproducible measurement, plus explicit unsupported cases. Commit: `feat(media): add consent-based virtual camera and audio routing`.
