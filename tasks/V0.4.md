# v0.4 — Secure IPC and managed child processes

Goal: Rust exclusively owns scrcpy and kdeconnect-cli process launch, stop, status and logs. Flutter invokes a typed local API and subscribes to events.

Deliverables:
1. Inspect repo baseline; set up Rust workspace crates: `nexus-domain` (device/session types), `nexus-application` (use cases), `nexus-ipc` (transport), `nexus-adapter-scrcpy`, `nexus-adapter-kde` or equivalently justified minimal arrangement.
2. Define versioned JSON (or equivalent) IPC contract: `ListDevices`, `PairDevice`, `Ping`, `ShareFile`, `StartMirror`, `StopMirror`, `GetSession`, `SubscribeEvents`; typed, stable errors. Record `protocol_version` and feature capability negotiation.
3. Enforce a per-user IPC trust boundary; document Windows/Unix transport policy, IPC message size limits, max clients and authenticated session assumption. No anonymous localhost HTTP as privileged command API.
4. Implement Rust-owned subprocess supervisor with no shell, validated args, output limits, child identity, exit handling, backoff (where appropriate), idempotent start/stop and explicit kill escalation. On failed startup emit actual error, not success.
5. Replace Flutter direct `dart:io Process` calls. Preserve UI behavior with real endpoint calls and event subscriptions. Device IDs from KDE not interchangeable with ADB serial.
6. Tests: command arg escaping, invalid ids, connection refusal, errors, timeouts, simultaneous start, shutdown during startup, unexpected exit, log cap, recovery. Add integration test with fake scrcpy and kde cli binaries. Manual acceptance: real KDE device list + real scrcpy start/stop on supported platform.

Non-goals: embedded video, message sync, rewriting KDE protocol, claiming performance numbers.

Exit gate: CI + manual acceptance checklist and honest known limitations. Commit: `feat(core): add secure IPC and process supervision`.
