# v0.5 — native video inside Flutter

Prerequisite: v0.4 merged, stable IPC and Rust session lifecycle.

Goal: expose a real platform-native Flutter Texture for a verified Android stream without embedding or screen-scraping an external scrcpy window.

Research first: investigate scrcpy official upstream server/client boundaries and supported integration/licensing; compare (A) maintainable upstream fork exposing frames via native API, (B) separate scrcpy-compatible streaming endpoint, (C) alternative Android MediaProjection companion. Choose based on maintenance and consent; do not assume scrcpy CLI can output stable raw frames. Respect stream protection and Android permissions.

Deliverables:
1. RFC with chosen media source protocol and exact upstream version, capture/control separation, codec/container, video timestamp origin, audio sync and legal review.
2. Native Windows/Linux/macOS backend using platform decoder (when available), Flutter `Texture` registrar ID and complete creation/disposal lifecycle. UI must show real stream or explicit unsupported/error state; never animated placeholder counted as success.
3. Codec negotiation, max dimensions/bitrate/fps controls, adaptive fallback, bounded frames (drop late frames rather than accumulating), reconnect and rotation handling. No frame decoding on Flutter UI isolate.
4. Comprehensive failure tests (missing codec, ADB disconnect, media server death, rapid start-stop, texture reuse, suspend-resume). Benchmarks with source, host OS, test phone and P50/P95/P99 latency.

Exit gate: user can interact with actual phone stream within Nexus Flutter window on at least one verified platform, with documented fallbacks for others. Commit: `feat(media): render Android streams in Flutter textures`.
